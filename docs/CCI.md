# CCI｜旅行社獲客網站核心定義

- **負責角色：** 網站企劃／週報編輯
- **輸入：** `AGENTS.md` 的專案目標、`research/travel-data.json`、`research/sources.md`、`docs/weekly-report.md`
- **產出：** 本文件；供 PRD、網站文案與驗收條件引用
- **資料依據：** 景點資料查詢日期 2026-10-28；週報報導期間 2026-10-22 至 2026-10-28
- **待確認：** 實際旅行社品牌、諮詢管道、可售行程、可報價資料、價格更新頻率及營運流程皆未提供
- **驗收狀態：** 通過（本課程指定 CCI 三項均轉為可執行產品原則；實際品牌資訊待確認）

## Core｜核心

幫助旅客快速找到適合自己的旅遊行程。

網站的主要價值是把旅客偏好轉成清楚的候選景點／行程提案，並說明推薦理由、資料來源及仍須確認的部分。第一版呈現「推薦提案」，不暗示資料已代表旅行社可售團、已訂位或保證成團。

## Clear｜明確

讓旅客用少量、容易回答的條件描述需求：

1. **旅遊對象：** 親子、情侶、熟齡旅客，可複選；再選填同行人數或兒童年齡區間等有助規劃的資料。
2. **預算：** 以「每人每趟新台幣總預算（NTD／人／趟）」為第一版統一單位。預算是旅客可接受的整趟預算上限；如果尚無各項成本資料，網站必須說明「價格尚未確認，不能判定是否符合預算」，不可把景點推薦誤說成預算內報價。
3. **天數：** 旅客輸入預計旅遊日數（天）。資料集沒有可驗證的行程天數時，只作為需求條件，不推定某景點必須停留幾天。
4. **旅遊風格：** 以可理解的主題標籤選擇，例如自然景觀、文化參觀、親子探索、城市景觀、散步休憩；標籤須對應資料欄位或明確標示為企劃分類。
5. **天候偏好（選填）：** 可開啟「雨天優先」，依已查核的室內／部分室內資料調整候選排序；雨天狀況、動線及當日營運未核實時明確標示待確認。

必要欄位以外均為選填。第一版不要求姓名、電話、電子郵件或精確生日；使用者主動要求諮詢時，聯絡資料另由後續諮詢步驟取得。

## Issue｜旅客問題

- 行程資訊太多，難以快速找到符合同行對象與興趣的選項。
- 景點特色、適合客群及行程條件散落在不同來源，彼此不容易比較。
- 旅客不知道如何開始選擇，也不清楚哪些價格、日期、營運或交通資訊還沒有核實。

## 產品原則

- 推薦理由要分清楚「來源已核實的景點特色」與「系統依偏好提出的建議」。
- 不符合條件時明確告知原因並提供可由旅客自行採用的放寬選項；不暗中放寬硬性條件。
- 資料狀態、來源、查詢日期與待確認欄位要在推薦卡片可見，不藏在僅供管理者查看的資料中。
- 無價格資料時不做預算符合／不符合的確定判斷，也不產生虛構報價。
